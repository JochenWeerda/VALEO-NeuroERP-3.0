deployment and operational support around third-party software. The

## Runtime and sidecar software (not merged into VALEO source)

These components typically run as separate processes/containers. Their licenses
apply to the images/distributions you deploy, not as a code merge into VALEO:

| Component | Typical license | Role |
|---|---|---|
| PostgreSQL | PostgreSQL License | Primary database |
| Redis / compatible | Image-dependent (RSALv2, SSPL, BSD, …) | Cache / queues |
| NATS Server | Apache-2.0 | Event bus (JetStream) |
| Keycloak | Apache-2.0 | OIDC identity provider |
| Paperless-ngx | GPL-3.0 | DMS sidecar — keep isolated from application code |
| nginx | BSD-2-Clause | Frontend reverse proxy (production image) |

Operators must verify the exact license of the container images pinned in
deployment manifests before commercial redistribution.

## Python and Node dependencies

- Backend: pinned in `requirements.txt` / service requirements; inventory via
  `python scripts/generate_license_inventory.py`.
- Frontend: `packages/frontend-web/package.json` and workspace lockfile; use the
  CI CycloneDX SBOM for complete transitive license data.

Common open-source licenses among backend dependencies include MIT, Apache-2.0,
BSD-2-Clause and BSD-3-Clause. Packages without metadata are marked `UNKNOWN`
in the inventory until resolved via SBOM.

## How to refresh

```bash
python scripts/generate_license_inventory.py
# CI: quality-gate → SBOM (CycloneDX) artefact valeo-neuroerp-sbom.cdx.json
```
