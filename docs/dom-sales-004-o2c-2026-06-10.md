# DOM-SALES-004 — Order-to-Cash (O2C) (2026-06-10)

Sprint-Ziel: durchgängiger O2C-Prozess Angebot→Auftrag→Lieferschein→Rechnung
(→Buchung→OP) mit Kreditlimit/Preis/Sammelbeleg. Erster Slice (004.1): O2C-Kette
sichtbar/prüfbar — inkl. Schließen der Modelllücke.

## Modelllücke geschlossen
`domain_sales.delivery_notes` hatte **keinen Auftragsbezug**. Migration
`sales_o2c_link_20260610` ergänzt additiv `sales_order_id` (nullable) + Index.

## Slice 004.1 — O2C-Spine (umgesetzt, read-only)
- Service: `app/services/o2c_chain_service.py`
  - `trace(auftrag)` — Angebot (sales_offers via `sales_offer_id`) → Auftrag
    (sales_orders) → Lieferschein(e) (delivery_notes via `sales_order_id`) →
    Rechnung(en) (delivery.invoice_number); kanonischer Status
    angebot→auftrag→geliefert→berechnet; Lücken (kein LS / keine Rechnung).
  - `list_orders()` — Picker mit Vollständigkeits-Flags.
- API: `GET /sales/o2c?auftrag=…` + `GET /sales/o2c/orders`.
- Seed: `scripts/seed_demo_sales.py` (idempotent) — DEMO-AUF-001 vollständige Kette
  (Angebot→Auftrag→LS→Rechnung), DEMO-AUF-002 Auftrag ohne Lieferschein (Lücke).
- Frontend: `pages/sales/auftragskette.tsx` (Picker + Ketten-Timeline + Lücken)
  + Hooks `lib/api/o2c-chain.ts` + Nav „Auftragskette (O2C)" + Route-Alias.

### Verifiziert (Seed-Daten)
DEMO-AUF-001: angebot→auftrag→lieferschein→rechnung, Status „berechnet", 0 Lücken.
DEMO-AUF-002: Status „auftrag", Lücke „Kein Lieferschein zum Auftrag".
Hinweis: `sales_orders.id` ist varchar, `sales_order_id` UUID → Join mit `::text`-Cast.

## Slice 004.2 — Positions-Match Auftrag↔Lieferschein (umgesetzt, 2026-06-11)
- Service: `app/services/sales_match_service.py` — match je Auftragsposition
  (`sales_order_items`) gegen gelieferte Menge (Summe `delivery_note_positions` über
  alle Lieferscheine des Auftrags, Schlüssel = Artikelnummer). Reuse der reinen
  `match_position` aus dem PROC-Match (offen/teil/voll/über, 1 % Toleranz) +
  reine `match_summary`. Offene Menge/Wert, Lücken, Lieferschein-Liste.
- API: `GET /sales/match?auftrag=…` + `GET /sales/match/orders`.
- Seed: `seed_demo_sales.py` ergänzt Lieferschein-Positionen für DEMO-LS-001
  (MILCHLEISTUNG-18 25/25 vollständig, MINERAL-RIND 3/5 teilgeliefert).
- Frontend: `pages/sales/auftrag-lieferschein-abgleich.tsx` (Auftrags-Picker +
  Positions-Match + Lieferscheine + Lücken) + Hooks `lib/api/sales-match.ts` + Nav
  „Auftrag-Lieferschein-Abgleich" + Route-Alias.
- Tests: `tests/test_sales_match.py` (5 grün, reine Logik).

### Verifiziert (Seed)
DEMO-AUF-001: Pos 1 vollständig (25/25), Pos 2 teilgeliefert (3/5, 1.800 € offen),
Abweichung + 1 Lücke. DEMO-AUF-002: Position offen (kein Lieferschein).
