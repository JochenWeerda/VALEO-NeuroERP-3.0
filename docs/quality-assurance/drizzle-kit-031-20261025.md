# drizzle-kit 0.31 in den Domaenenpaketen (2026-10-25)

Slice `DRIZZLE-KIT-031-20261025`, Zweig `claude/drizzle-kit-031-20261025`,
Basis `5468de5ce` (PR #41, [dev-dependency-security-20261025.md](dev-dependency-security-20261025.md)).

## Ausgangslage

13 TS-Domaenenpakete deklarierten `drizzle-kit ^0.22.0` (installiert 0.22.8) neben
`drizzle-orm ^0.45.2`. drizzle-kit 0.22 bricht gegen orm 0.45 mit "This version of
drizzle-kit is outdated" ab; die Skripte riefen ausserdem `generate:pg`, `up:pg`,
`check:pg` (seit 0.21 entfallen) und `down:pg` (gab es in drizzle-kit nie:
`error: unknown command 'down:pg'`). Kein Migrationsskript dieser Pakete war lauffaehig.
Kein Sicherheitsbefund (der volle Audit war bereits auf node-forge reduziert).

## Aenderungen

| Paket | Massnahme |
| --- | --- |
| analytics, contracts, crm, pricing, quality, regulatory, sales, scheduler, weighing | `drizzle-kit ^0.31.11`; `generate:pg`/`up:pg`/`check:pg` -> `generate`/`up`/`check`; `migrate:down` (`down:pg`) entfernt |
| analytics, scheduler | zusaetzlich `db:reset` entfernt (lief ueber das nie existente `migrate:down`) |
| audit, document, notifications | nur `drizzle-kit ^0.31.11` (Skripte waren bereits im neuen Format) |
| crm | `drizzle.config.ts` von `driver: 'pg'`/`connectionString` auf `dialect: 'postgresql'`/`url` |
| delivery | kein Schema, keine Konfiguration, keine Migrationen: drizzle-kit und `migrate:*`/`db:studio` entfernt (wie production-domain in PR #41) |
| analytics README | Migrationsbefehle an die tatsaechlichen Skripte angepasst |

Semantik bewusst nicht umgedeutet: `migrate:up` bleibt `drizzle-kit up` (Snapshot-Upgrade,
wie `up:pg` frueher), nicht `migrate` gegen eine Datenbank. drizzle-kit kennt keine
Down-Migrationen; ein Rueckweg braucht eine Vorwaertsmigration.

Lockfile: nur `drizzle-kit@0.22.8` und `@esbuild-kit/esm-loader` entfallen, alle
Verbraucher auf `drizzle-kit@0.31.11`. `config/security/npm-backport-reviews.json`:
nur `lock_sha256` (node-forge, braces) neu gebunden, Manifest unveraendert.

## Befunde (nicht in diesem Slice geaendert)

- **scheduler-domain, Laufzeitfehler:** `src/infra/db/schema.ts:127-129` definiert drei
  Indizes (`schedule_runs_idx`, `job_runs_idx`, `runs_tenant_time_idx`) ausserhalb der
  Tabellendefinition. drizzle-orm 0.45 wirft dabei beim Modulimport
  `SyntaxError: "undefined" is not valid JSON`. `src/infra/db/connection.ts` importiert
  das Schema; der Dienst kann so nicht starten. Unabhaengig von drizzle-kit. Behebung:
  Indizes in den Tabellen-Callback von `runs` verschieben (keine Migrationen vorhanden).
- **audit, document, notifications:** `migrations/meta/_journal.json` verweist auf
  `0000_*.sql`, die Dateien fehlen (nur Snapshot eingecheckt). `drizzle-kit migrate`
  wuerde scheitern.
- **analytics, scheduler:** `db:seed` verweist auf nicht vorhandenes `scripts/seed-database.ts`.
- **RELEASE-RUNBOOK.md** nennt fuer document-domain `npm run migrate:down` als Rollback;
  das Skript gab es dort nie, drizzle-kit hat keine Down-Migrationen.
- hr: doppelte Indexnamen, testcontainers undeklariert (aus PR #41 offen).
- Keine Aussage ueber vollstaendige Sicherheit oder Gesamtfreigabe.
