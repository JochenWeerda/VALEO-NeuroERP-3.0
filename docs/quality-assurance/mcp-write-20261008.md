# MCP-WRITE 2026-10-08

## Lieferung

| Tool | Risiko | Schreiben |
|------|--------|-----------|
| `crm.activity.create` | medium | `domain_crm.activities` mit `tenant_id` aus Token |
| `sales.invoice.post` | high | Verkaufsrechnung `entwurf` nur nach `agent_proposals.approval_status=approved` |

`sales.invoice.propose` / `execute` bleibt **501** (kein Buchungs-Bypass).
FIBU-Journal und offene Posten entstehen weiter nur im UI-Pfad
`POST .../delivery-notes/{id}/create-invoice`; MCP setzt `fibu_journal: false`.

## Mandanten-ID

- Quelle: verifizierter Token-Claim `tenant_id` **oder** Alias `mandanten_id`
- `X-Tenant-ID` muss zum Claim passen (sonst 403)
- Parameter `tenant_id` / `mandanten_id` / `approval_granted` sind verboten (422)
- Kundenlookup für Aktivitäten: `domain_crm.customers WHERE tenant_id = :tenant`
  (kein Cross-Tenant-Fallback über `public.kunden`)
