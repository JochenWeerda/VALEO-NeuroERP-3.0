== AUFGABE ==

Du erhaeltst `unified_findings.json` — aggregierte Ergebnisse aus:
Gitleaks, Semgrep, Bandit, Trivy (fs + config + image).

Fuehre eine 4-stufige Analyse durch:

── STUFE 1: ANALYSE ──
Fuer jedes Finding bewerte:
- Ist es ein echtes Sicherheitsproblem oder ein False Positive?
- Ist es im Kontext dieses Systems relevant?
- Beruecksichtige: Dev-Tokens, Test-Fixtures und Beispiel-Daten sind KEINE echten Secrets

── STUFE 2: RED TEAM ──
Fuer jedes bestaetigte Finding:
- Beschreibe ein konkretes Angriffsszenario (max 3 Saetze)
- Welche Vorbedingungen braucht der Angreifer?
- Was ist der maximale Schaden (Datenabfluss, RCE, Privilege Escalation, DoS)?

── STUFE 3: BLUE TEAM ──
Bewerte die reale Ausnutzbarkeit:
- Gibt es mitigierende Faktoren (Auth-Middleware, Tenant-Isolation, Network-Policies)?
- Wie wahrscheinlich ist eine Ausnutzung in der realen Deployment-Umgebung?
- Vergib eine finale Risiko-Einstufung: CRITICAL / HIGH / MEDIUM / LOW / FALSE_POSITIVE

── STUFE 4: FIXER ──
Fuer jedes Finding mit Risiko >= MEDIUM:
- Exakter Fix mit Code-Snippet (vorher → nachher)
- Minimale Aenderung, kein Over-Engineering
- Bei Dependency-Vulns: exakte Zielversion

== OUTPUT-FORMAT ==

Liefere fuer jedes Finding:

```
### [FINALE_SEVERITY] Titel
- **Scanner:** ...
- **Datei:** ...
- **Kategorie:** ...
- **Angriffsszenario:** ...
- **Vorbedingungen:** ...
- **Mitigierende Faktoren:** ...
- **Finale Bewertung:** CRITICAL|HIGH|MEDIUM|LOW|FALSE_POSITIVE
- **Fix:**
  ```diff
  - alter Code
  + neuer Code
  ```
```

Am Ende liefere eine priorisierte Zusammenfassung:
1. Sofort beheben (CRITICAL)
2. Diese Woche (HIGH)
3. Naechster Sprint (MEDIUM)
4. Entfernte False Positives (kurze Liste)

== WICHTIGE REGELN ==
- Ignoriere Low-Confidence und rein theoretische Issues
- API_DEV_TOKEN, test-secret-for-ci und aehnliche Test-Tokens sind KEINE echten Leaks
- Bandit B101 (assert) in Tests ist ein False Positive
- requirements.txt Pinning-Warnungen sind LOW, nicht HIGH
- Fokus auf OWASP Top 10, besonders: Injection, Broken Auth, SSRF, Path Traversal
- Bei Multi-Tenant-System: Tenant-Isolation-Bypass ist immer CRITICAL
- Sei praezise, kein Fluff
